# 1.5.0

Подзадача C-2 эпика #76 (Tauri 2 + Go-служба). Для человека ничего не меняется: окно, вход, серверы,
уведомления, «Не через VPN» — те же. Меняется состав файлов.

- **Две программы вместо одной.** `Boop.exe` — только окно и трей; `BoopService.exe` — служба
  `BoopVPN` (Wintun, AmneziaWG, Xray-core, маршруты, DNS, раздельное туннелирование, WFP kill switch,
  pipe-сервер). Режима `Boop.exe --service` и аварийного режима «окно с правами администратора»
  (`--embedded`) больше нет. Установщик кладёт оба файла в `%ProgramFiles%\Boop`.
- **`Boop.exe` не содержит движка:** ни Xray-core, ни AmneziaWG, ни gVisor (проверка в CI,
  `scripts/check-deps.sh`, по списку пакетов и по собранным файлам). `BoopService.exe` — консольная
  программа без WebView2, трея и тостов (`-H windowsgui` нет, пакетов окна и `toast` в ней нет).
- **Версионируемый pipe-протокол.** Поле `proto` в каждом запросе, `protocol`/`minProtocol` в каждом
  ответе, правило «служба понимает текущую и предыдущую версию»; при несовпадении окно пишет «обновите
  службу» или «обновите Boop VPN». Протокол 1 — это 1.4.x. Описание: `helper/PROTOCOL.md`. ACL pipe и
  проверка клиента не менялись.
- **Совместимость с 1.4.x.** Окно 1.5.0 работает со службой 1.4.x (`Boop.exe --service`, имя `BoopVPN`,
  протокол 1) и не заставляет её переустанавливать; окно 1.4.x — со службой 1.5.0. Установщик 1.5.0
  поверх 1.4.x останавливает службу, заменяет `Boop.exe`, кладёт `BoopService.exe` и перенацеливает ту же
  службу `BoopVPN` на него.
- **Обновление службы — только установщиком.** Манифест `desktop.json` называет один файл (`Boop.exe`),
  а подмена им `BoopService.exe` убила бы службу. Поэтому служба 1.5.x на `update` отвечает отказом
  (`the service is updated by the setup program`); окно обновляет только собственный `Boop.exe`, а там,
  где папка не пишется (Program Files), просит запустить новый установщик. Перевод обновления на
  установщик — этап C-5.
- Где живёт `core.App` и как к нему подключится оболочка Tauri — решение в `ARCHITECTURE.md`
  («ADR: граница окно/служба»). Код этого решения — этап C-4.
- `build.sh` собирает оба файла (у каждого свой `winres`: окно `asInvoker`, служба без UI), оба проходят
  через `BOOP_SIGN`, SHA-256 считается после подписи; `Boop-Setup` собирается из двух файлов.
- Версия: `1.5.0` в `build.sh`, `winres/*.json`, `installer/boop.iss`.

Проверка и ограничения — в описании PR.

## Нельзя публиковать через `desktop.json`

1.5.0 **нельзя** выкладывать в поля `desktop.json`, которые читает 1.4.x. Служба 1.4.x (`Boop.exe --service`, SYSTEM) подменила бы `Boop.exe` на окно 1.5.0 и перезапустилась — а `BoopService.exe` на диске нет. 1.5.0 доставляется только установщиком (`Boop-Setup`), он кладёт оба файла и перенацеливает службу `BoopVPN`. Правило действует для этапов C-5 и C-6 (#76).

Защита: `Boop.exe` 1.5.0, запущенный с `--service` (старая запись SCM), окно не открывает, пишет причину в `%ProgramData%\Boop\service-legacy.log` и выходит с кодом 11. Управление `BoopService.exe` не передаётся: SCM ждёт `StartServiceCtrlDispatcher` от того процесса, который запустил, дочерний его вызвать не может.
