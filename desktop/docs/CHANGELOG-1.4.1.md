# Boop 1.4.1 (Windows): служба снова устанавливается (P0, #65)

## Что было не так в 1.4.0
Установщик службы падал на первом же шаге: `SecureDir` назначал владельцем каталога SYSTEM, а для этого
у процесса должна быть **включена** привилегия `SeRestorePrivilege` (у администратора она есть, но выключена).
Windows отвечала `ERROR_INVALID_OWNER` (1307), служба не создавалась, окно показывало «код 2». Причину
не было видно в логах: `install.log` открывался только после этого же шага.

## Что изменилось
* **Установка службы.** Перед сменой владельца включаются `SeRestorePrivilege` и `SeTakeOwnershipPrivilege`.
  Владелец: SYSTEM, если нельзя — `Administrators`, если и так нельзя — только защищённый список доступа
  (он и закрывает каталог для обычных пользователей). Установка больше не падает из-за владельца.
* **Реальная ошибка.** `install.log` открывается до любых действий (`%ProgramData%\Boop`, иначе `%TEMP%`,
  иначе `%LOCALAPPDATA%\Boop`). Каждый шаг называется (`secure-program-dir`, `copy-program`, `create-service`,
  `start-service`…); в журнал и в окно попадает шаг, код Windows и его текст. Код выхода установщика при ошибке — 10
  (не 2, он зарезервирован за рантаймом Go); причину повышенный процесс передаёт окну через файл
  `%LOCALAPPDATA%\Boop\install-result.txt`.
* **Резервный режим без службы.** Не удалась установка (любая ошибка или отказ в UAC) — окно запускается
  заново с правами администратора (`--embedded`, один UAC) и держит туннель в своём процессе, как в 1.3.x;
  в окне появляется сообщение об этом. VPN не зависит от службы.
* **Обновление без службы.** Если служба не отвечает, окно заменяет собственный `Boop.exe` (`SwapBinary`) и
  перезапускается с `--updated`. Если каталог не даёт писать (`Program Files`) — один UAC и повышенная копия
  (`--self-update`), которая сама берёт манифест у панели и проверяет SHA-256 и подпись, как служба.
  Ничего из окна она не принимает.
* **Автозапуск.** Задача планировщика `Boop VPN` старых версий удаляется только когда служба установлена и
  отвечает. Окно, запущенное автозапуском (`--tray`), не вызывает UAC само: запрос будет при первом подключении.
* **Восстановление сломанной 1.4.0.** Установка идемпотентна: 1.4.1, запущенная поверх 1.4.0 из любой папки,
  сама чинит права на `%ProgramFiles%\Boop` и `%ProgramData%\Boop`, пересоздаёт службу, запускает её и
  обновляет Run-ключ. 1.3.1 поверх 1.4.0 (по коду, на Windows не проверено): её
  манифест требует администратора и она запускает туннель в своём процессе, службу не использует; если служба 1.4.0
  работает и держит туннель, два туннеля могут конфликтовать — остановить службу (`Boop.exe --uninstall-service`).
* **CI.** Новый обязательный джоб `windows-service` на `windows-latest`: `Boop.exe --install-service` →
  код 0, служба `BoopVPN` Running, пайп есть, права каталога, повторная установка (апгрейд) → 0,
  `--uninstall-service` → 0, служба и файлы удалены.
* Протокол, параметры обфускации, конфиги VLESS/xray, API панели и `desktop.json` не менялись.

## Ручная проверка на Windows
1. Чистая Windows, `Boop.exe` из загрузок: один UAC, служба `BoopVPN` Running, окно открывается из `%ProgramFiles%\Boop`.
2. Поверх 1.3.1 через автообновление: один UAC, задача «Boop VPN» удалена только после успешного старта службы, автозапуск работает через `Run`.
3. Поверх сломанной 1.4.0 (вручную): запустить 1.4.1, принять UAC — служба создана и работает.
4. Отказ в UAC при установке службы: второй запрос UAC для резервного режима; согласие — окно с сообщением о резервном режиме, VPN подключается; отказ — понятная ошибка в окне, «Повторить» работает.
5. Искусственная ошибка (например, занять `%ProgramFiles%\Boop\Boop.exe` без возможности замены): в окне шаг и код Windows, в `%ProgramData%\Boop\install.log` то же.
6. Обновление 1.4.1 → 1.4.2 (тестовый манифест) со службой: служба перезапускается, окно стартует заново.
7. То же без службы (остановить и удалить её, оставить окно из загрузок): обновление идёт заменой своего файла, без UAC; из `Program Files` — с одним UAC.
8. Автозапуск после перезагрузки при работающей службе: окно в трее без UAC; без службы: в трее, UAC при первом подключении.
