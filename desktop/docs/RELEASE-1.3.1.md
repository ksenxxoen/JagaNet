# Выпуск Boop 1.3.1: как опубликовать

Срочное исправление к 1.3.0 (issue #53, [CHANGELOG-1.3.1.md](CHANGELOG-1.3.1.md)). Порядок тот же,
что у 1.3.0 — [RELEASE-1.3.0.md](RELEASE-1.3.0.md); ниже только отличия. Серверы и панель не
меняются.

## Сборка

```sh
cd desktop
./build.sh 1.3.1           # dist/Boop.exe (Go 1.27.3: build.sh сам ставит GOTOOLCHAIN)
./build-linux.sh 1.3.1     # dist/boop_1.3.1~ubuntu22.04_amd64.deb, …~ubuntu24.04… (+ .sha256)
```

## Подпись — до хэша

Сертификата для подписи кода сейчас нет, поэтому 1.3.1, как и 1.3.0, выходит **без подписи
Authenticode** (SmartScreen может предупредить при первом запуске скачанного файла; обновление
из Boop 1.3.0 работает и без подписи — клиент проверяет SHA-256 из манифеста).

Когда сертификат появится, порядок строго такой ([SIGNING.md](../SIGNING.md)):

1. `BOOP_SIGN=azure ./build.sh 1.3.1` (или `BOOP_SIGN=osslsigncode`) — подпись exe;
2. `osslsigncode verify -in dist/Boop.exe` — `Succeeded`;
3. только **после** подписи считать хэш (`dist/Boop.exe.sha256` пишет подписанная сборка) и
   ставить его в `sha256` в `desktop.json`. Хэш неподписанного файла к подписанному не подходит —
   клиенты откажутся ставить обновление (`sha256 mismatch`).

## Манифесты

```json
desktop.json        {"version":"1.3.1","mandatory":false,"notes":"Исправлено подключение к новым локациям","sha256":"<sha256 Boop.exe>"}
desktop-linux.json  {"version":"1.3.1","mandatory":false,"notes":"Исправлено подключение к новым локациям"}
```

Файлы в `DOWNLOADS_DIR` — те же имена, что у 1.3.0 (`Boop.exe`, `boop-ubuntu22.04.deb`,
`boop-ubuntu24.04.deb`), манифесты — последними.

## Проверить

- `curl -s https://boopvpn.app/v1/app/desktop | jq .version` → `"1.3.1"`; `sha256` = хэш
  `Boop.exe`, который лежит в `DOWNLOADS_DIR`.
- На Windows с 1.3.0: баннер «Доступно обновление · 1.3.1», после установки в настройках
  «Boop 1.3.1».
- **Главное:** подключиться к стране с новыми серверами (VLESS) — «Подключено», сайты открываются.
  В `%LOCALAPPDATA%\Boop\boop.log`: `xray: core: Xray 26.10.29 started`, `vless: using tcp:443`,
  нет `failed to find an available destination`.
- Сервер, который не отвечает (например, адрес сервера заблокирован правилом файрвола на
  роутере): через 45 с
  «Не удалось подключиться» и «Повторить», попыток сама программа больше не делает; «Повторить»
  начинает заново. Со строгим режимом интернет остаётся закрытым.

## Откат

Вернуть файлы и манифесты 1.3.0. Клиенты 1.3.1 сами на 1.3.0 не откатываются.
