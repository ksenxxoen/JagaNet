# Проверка Boop на антивирусах (ручная методика)

Живые антивирусы в CI запустить нельзя, поэтому это пошаговая инструкция для ручной
проверки в чистой виртуальной машине. Автоматическая часть — `desktop/scripts/forbidden-calls.sh`
(статическая проверка) и отчёт о дочерних процессах в job `windows-installer`
(см. `desktop/ARCHITECTURE.md`, «Проверка запрещённых вызовов»). Основание —
`docs/desktop-architecture-options.md`, эпик #76.

Цель: до и после каждого этапа эпика получить таблицу «сценарий → антивирус → вердикт»
и по ней видеть, что детектов стало меньше.

## 1. Подготовка

1. Виртуальная машина Windows 10 или 11 x64 (Hyper-V, VirtualBox или VMware), 4 ГБ ОЗУ,
   интернет есть. Установите чистую систему, обновления Windows, **WebView2 Runtime**
   (есть в Windows 11 и в свежей Windows 10 с Edge). Запишите номер сборки (`winver`).
2. Снимите снапшот **«clean»**. Каждый антивирус ставится на отдельную копию этого снапшота:
   - **Microsoft Defender** — уже в системе; обновите базы: `Update-MpSignature` в PowerShell
     администратора или Безопасность Windows → Защита от вирусов → Обновления.
   - **Kaspersky Premium** — пробная версия на https://www.kaspersky.ru/downloads (30 дней).
     После установки обновите базы и включите облачную защиту (KSN), как у обычного пользователя.
   - **ESET** (NOD32 / Internet Security) — пробная версия на https://www.eset.com/ru/home/download/.
     Базы обновить, LiveGrid включить.
3. После установки антивируса и обновления баз отключите сеть на минуту, снимите снапшот
   **«clean-<антивирус>»** и работайте только с ним. Перед каждым прогоном возвращайтесь к нему.
4. Скачайте Sysinternals **Process Monitor** (https://learn.microsoft.com/sysinternals/downloads/procmon),
   положите `Procmon64.exe` рядом со скриптом `av-trace.ps1`. Запишите версию антивируса и баз.
5. Возьмите проверяемую сборку: `Boop-Setup-<версия>.exe` и `Boop.exe` из артефактов CI или релиза.
   Запишите SHA-256 (`Get-FileHash`). Скачивайте их **в браузере**, как пользователь: так
   файл получает метку «из интернета» (Mark of the Web), и антивирус видит его как обычную загрузку.

## 2. Как записывать (Process Monitor)

Для каждого сценария из §3 запускайте в PowerShell администратора:

```powershell
powershell -ExecutionPolicy Bypass -File .\av-trace.ps1 -Scenario 02-install -Av Defender
```

Скрипт запускает Process Monitor, ждёт, пока вы пройдёте сценарий руками, затем сохраняет
`av-results\<Av>-<Scenario>.pml`, полный `.csv` и `…-suspicious.csv` с подозрительными событиями.
Скрипт не входит в дистрибутив и приложением не вызывается.

Если нужно руками открыть `.pml` в Process Monitor, фильтры (Filter → Filter…, Include):

| Столбец | Условие | Значение |
|---|---|---|
| Operation | is | `Process Create` и Path ends with `schtasks.exe`, `reg.exe`, `powershell.exe`, `pwsh.exe`, `cmd.exe`, `wscript.exe`, `mshta.exe`, `rundll32.exe`, `regsvr32.exe`, `takeown.exe`, `icacls.exe` |
| Operation | is | `SetSecurityFile` (смена прав/владельца) |
| Operation | is | `RegSetValue`, `RegCreateKey`, `RegDeleteValue` при Path contains `\CurrentVersion\Run` (HKCU и HKLM) |
| Operation | is | `CreateFile` при Path ends with `.exe`/`.dll`/`.sys` и Detail contains `Disposition: Create` — файлы, созданные не установщиком (процесс не `Boop-Setup*.exe`/`unins*.exe`) |

Что **искать** и считать замечанием:

1. `Process Create` для `schtasks.exe`, `reg.exe`, `powershell.exe`, `cmd.exe` с родителем `Boop.exe`.
2. `SetSecurityFile` из процесса `Boop.exe` (смена владельца/DACL).
3. Изменения `HKCU\…\CurrentVersion\Run` / `HKLM\…\CurrentVersion\Run` из `Boop.exe`
   (из установщика — ожидаемо).
4. Появление `.exe`/`.dll` рядом с `Boop.exe` в «Загрузках» или в другом месте, кроме `%ProgramFiles%\Boop`
   и работы установщика.
5. Переименование/подмена своего `Boop.exe` (`.old`, `.new`).

## 3. Сценарии

Для **каждого** антивируса вернитесь к его снапшоту и пройдите по порядку. Перед каждым пунктом,
где это сказано, запускайте `av-trace.ps1`. После пункта запишите в таблицу (§4) вердикт:
**ок** / **предупреждение** (антивирус спросил, показал окно) / **блок** (файл удалён, помещён в карантин
или запуск остановлен) и название угрозы из журнала антивируса.

| № | Сценарий | Что делать | Запись |
|---|---|---|---|
| 01 | Скачивание | Скачать `Boop-Setup-<версия>.exe` в браузере в «Загрузки». Дождаться окончания. Подождать 2 минуты (фоновая проверка) | — |
| 02 | Запуск установщика | Запустить `Boop-Setup` двойным щелчком, пройти мастер с настройками по умолчанию (UAC — «Да») | procmon |
| 03 | Первый запуск | Запустить Boop из меню «Пуск». Дождаться окна | procmon |
| 04 | Вход | Войти (по токену или по ссылке из Telegram-бота). Дождаться списка нод | procmon |
| 05 | Подключение, протокол AmneziaWG | Выбрать ноду/режим на AmneziaWG, подключиться, открыть сайт, проверить IP | procmon |
| 06 | Подключение, VLESS Vision | То же на VLESS Vision | procmon |
| 07 | Подключение, VLESS XHTTP | То же на VLESS XHTTP | procmon |
| 08 | Отключение | Отключиться, проверить, что интернет без VPN работает | procmon |
| 09 | Автозапуск | Включить автозапуск в настройках, выключить, снова включить | procmon |
| 10 | Перезагрузка | Перезагрузить VM, войти, проверить, что Boop запустился и служба `BoopVPN` работает | — |
| 11 | Обновление | Установить поверх предыдущей версии `Boop-Setup-<следующая>.exe` (а для версий 1.4.x — дождаться самообновления из окна) | procmon |
| 12 | Прямой запуск из «Загрузок» | Откатиться к снапшоту, скачать `Boop.exe` (без установщика), запустить из «Загрузок». Проверить, что рядом не появились `.dll`, нет автозапуска и службы | procmon |
| 13 | Удаление | «Параметры → Приложения → Boop → Удалить» (с очисткой данных и без) | procmon |

Для сценариев 05–07 нужен рабочий аккаунт с доступом к нодам.

## 4. Таблица результатов

Скопируйте шаблон в `docs/av-results/<дата>-<версия>.md` (папку создайте; результаты в репозитории
хранятся для сравнения между версиями) и заполните. Прикладывайте `…-suspicious.csv` и скриншоты
окон антивируса к PR или заметке.

```markdown
# Результаты проверки на антивирусах: Boop <версия>, <дата>

Сборка: <имя файла>, SHA-256 <…>. VM: Windows <10/11> build <…>. Проверял: <имя>.

| Антивирус (версия, базы от) | Сценарий | Вердикт (ок / предупреждение / блок) | Название угрозы | Действие антивируса | Замечания Process Monitor |
|---|---|---|---|---|---|
| Defender 4.18.…, 2026-11-02 | 01 Скачивание | ок | — | — | — |
| Defender … | 02 Запуск установщика | | | | |
| Kaspersky … | 01 Скачивание | | | | |
| ESET … | 01 Скачивание | | | | |
```

Строк — по одной на пару «сценарий × антивирус» (13 × 3 = 39). Если антивирус заблокировал файл,
следующие сценарии для этой копии не проходятся: пометьте «не проверялось, см. 0X».

## 5. Ложное срабатывание: куда отправлять

Только после того, как убедились, что файл — настоящая сборка (SHA-256 совпадает с CI/релизом).
Прикладывайте сам файл, SHA-256 и короткое описание «VPN-клиент Boop, <версия>, подпись <есть/нет>».

1. **Kaspersky** — сайт **OpenTIP**: https://opentip.kaspersky.com/ → вкладка File, загрузить файл,
   «Report incorrect verdict / Запросить пересмотр»; для заявки на белый список — программа
   Allowlist: https://opentip.kaspersky.com/allowlist (форма для разработчиков).
2. **Microsoft Defender** — **WDSI**: https://www.microsoft.com/wdsi/filesubmission → «Software developer»,
   загрузить файл, указать название угрозы из журнала Defender («Защита от вирусов → Журнал защиты»).
3. **ESET** — https://support.eset.com/en/kb141-submit-a-sample-to-the-eset-lab (для ложных срабатываний:
   отправить файл с темой «False positive» на samples@eset.com или через форму по ссылке).

Порядок: (1) сохранить имя угрозы и скриншот; (2) отправить в тот антивирус, который сработал;
(3) записать номер обращения в таблицу результатов; (4) повторить сценарий после обновления баз
(обычно 1–3 дня).
